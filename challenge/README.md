======================================================================
FIX MY CODE
======================================================================

DESCRIPTION
-----------
Ce projet introduit un nouveau type d’exercice : corriger du code existant.

Contrairement aux projets classiques où vous écrivez tout depuis zéro,
ici vous devez :

    - analyser un code déjà écrit,
    - comprendre son intention,
    - identifier les bugs,
    - corriger uniquement ce qui est nécessaire,
    - sans réécrire entièrement le programme.

Le but est de développer vos compétences en débogage, lecture de code,
compréhension de logique, et correction ciblée.

----------------------------------------------------------------------
BACKGROUND CONTEXT
------------------
Le repository fourni contient plusieurs programmes dans différents langages.
Certains vous seront familiers, d’autres non.

Votre mission :
    - télécharger le repository Fix_My_Code_Challenge,
    - utiliser les fichiers fournis comme base,
    - corriger les erreurs,
    - améliorer le comportement uniquement lorsque c’est nécessaire.

Important :
    Vous ne devez **pas** recoder tout le projet.
    Vous devez **corriger** le code existant.

----------------------------------------------------------------------
REQUIREMENTS
------------
GENERAL
    - Éditeurs autorisés : vi, vim, emacs
    - Tous les fichiers seront interprétés/compilés sur Ubuntu 14.04 LTS
      avec Python 3.4.3 (selon les exercices)
    - Tous les fichiers doivent se terminer par une nouvelle ligne
    - Tous les fichiers doivent être exécutables
    - La première ligne de tous les fichiers Python doit être exactement :
          #!/usr/bin/python3
    - Un fichier README.md est obligatoire à la racine du projet
    - Le code doit respecter PEP 8 (version 1.7.x)
    - Vous devez utiliser le repository fourni comme base

----------------------------------------------------------------------
OBJECTIF GLOBAL
---------------
Ce projet vous apprend à :
    - lire et comprendre du code écrit par quelqu’un d’autre,
    - identifier les erreurs logiques, syntaxiques ou structurelles,
    - corriger un bug sans casser le reste du programme,
    - améliorer la robustesse du code existant,
    - travailler sur un code base réel, comme dans un environnement pro,
    - éviter les réécritures inutiles et se concentrer sur la correction.

----------------------------------------------------------------------
CONSEILS
--------
    - Lisez le code avant de toucher quoi que ce soit.
    - Comprenez l’intention du développeur original.
    - Reproduisez les bugs pour les comprendre.
    - Corrigez uniquement ce qui est nécessaire.
    - Testez après chaque modification.
    - Ne réécrivez pas tout : ce n’est pas le but du projet.
